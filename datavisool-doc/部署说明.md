# 部署说明

本说明适用于当前版本的 `datavisool-web-v<版本号>-release.zip` 发布包。

这是一个标准 ZIP 压缩包，可以直接用系统自带压缩工具、Windows 资源管理器、macOS Finder 或 7-Zip 解压。

压缩包内包含：

- `server.jar`
- `component-docs/`（与本次应用构建匹配的内置组件文档）
- `部署说明.md`
- `config/application.yml`（配置模板）
- Windows 启动脚本 `deploy_windows.cmd`、`deploy_windows.ps1`
- Linux 启动脚本 `deploy_linux.sh`；macOS 启动脚本 `deploy_macos.command`（调用 `deploy_linux.sh`）

其中 `server.jar` 是最终交付的服务程序；`component-docs/` 必须随完整发布包解压到 JAR 同目录，供 AI 组件规格和数据契约功能读取；`config/application.yml` 是常规部署配置模板。部署脚本不依赖 Node.js，也不会自动安装 Java。

## 提示语言 / Prompt language

启动脚本根据系统语言自动选择中文或英文；其他语言默认显示中文。可在启动前设置 `DATAVISOOL_LANG=zh-CN` 或 `DATAVISOOL_LANG=en-US` 覆盖自动选择。Linux/macOS 示例：`DATAVISOOL_LANG=en-US ./deploy_linux.sh`；Windows CMD 示例：`set DATAVISOOL_LANG=en-US`，然后运行 `deploy_windows.cmd`。应用、数据库和 Docker 自身输出的日志不受此设置控制。

The launcher selects Chinese or English from the system language and falls back to Chinese. Set `DATAVISOOL_LANG=zh-CN` or `DATAVISOOL_LANG=en-US` to override it. On Linux/macOS, run `DATAVISOOL_LANG=en-US ./deploy_linux.sh`; in Windows CMD, run `set DATAVISOOL_LANG=en-US` before `deploy_windows.cmd`. Application, database and Docker logs are not translated by this setting.

## 部署前准备

请先准备好以下内容：

- 一台可运行 Java 17 的服务器
- 一个可用的 MySQL 数据库
- 一个用于放置服务程序且可写的目录，例如 `/usr/app/datavisool-server`；默认资源和 AI 数据也保存在该启动工作目录下
- 解压目录可写；配置文件已位于 `config/application.yml`

## 推荐快速开始

首次使用空数据库时，启动器会提示设置管理员密码（至少 8 个字符、最多 72 个 UTF-8 字节）；输入不回显，也不会保存到配置文件。非交互环境可在启动前设置 `DATAVISOOL_ADMIN_PASSWORD`。已有数据库不会要求或重置管理员密码。

应用在数据库初始化前检查实际解析后的 `server.port` 和 `server.address` 是否能够绑定；端口被占用或地址不可用时会停止并提示。`server.port=0` 由系统分配端口，不做固定端口占用检查。该检查不会预留端口，之后仍可能出现其他进程抢占。

1. 将本次发布包上传到目标服务器并解压到固定的服务运行目录。
2. 启动对应平台的入口：Windows 双击 `deploy_windows.cmd`；macOS 双击 `deploy_macos.command`，若系统拦截则在终端运行 `sh deploy_linux.sh`；Linux 运行 `sh deploy_linux.sh`。
3. 模板默认连接本机 MySQL（`127.0.0.1:3306`），数据库名、用户名和密码均留空。首次启动会依次询问这三项，密码输入不回显；已有有效值会保留，只询问缺失项。数据库名限 1–64 位字母、数字、下划线或短横线，写入 JDBC URL 时保留主机、端口和查询参数。远程 MySQL 请先修改 `config/application.yml` 中的主机和端口。若 URL 行缺失、格式无效或主机无效（包括旧占位地址 `mysql-host`），请恢复模板或手动修正，脚本不会猜测地址。修改前生成 `config/application.yml.bak.<时间戳>.<唯一后缀>` 备份，已有备份会保留，随后应用在后台启动。
4. 用浏览器访问服务地址，确认页面和接口可正常打开。保持解压目录不变，使默认数据路径和本地运行记录保持一致。

无参数运行会检查 Java 17 并交互补齐数据库名、用户名和密码；已填写的有效值会保留，只询问缺失项。数据库名写入 JDBC URL 时保留主机、端口和查询参数。URL 格式、主机无效时需恢复模板或手动修正，脚本不会猜测地址。`--check` 只读检查 Java 和配置，不询问、不改文件、不启动。`--status` 查看、`--stop` 停止由当前发布目录记录的实例；这两个操作不要求 Java 或数据库配置通过检查。`--restart` 会先停止该目录记录的实例，停止成功后再按正常启动流程运行；如果实例未运行，则直接启动；若停止失败或 Linux/macOS 等待超过 15 秒，则不会启动第二个实例。例如 Linux/macOS 执行 `sh deploy_linux.sh --restart`，Windows 执行 `deploy_windows.cmd --restart`；`--help` 显示帮助。重复启动不会为同一发布目录再启动第二个实例。脚本会在后台启动 Java：Linux/macOS 日志写入 `logs/startup.log`，Windows 标准输出和错误分别写入 `logs/startup.stdout.log`、`logs/startup.stderr.log`；PID 记录在 `run/application.pid`，Linux/macOS 的实例信息在 `run/application.start`，Windows 的实例信息在 `run/application.json`。Linux/macOS 停止时发送 TERM 并最多等待 15 秒，不会强制结束；Windows 停止时直接终止 Java 进程，不能保证 Java 关闭钩子执行，建议在没有重要请求或写入进行时停止。启动时等待应用启动并检查本机 HTTP 接口，最长 120 秒；超时不表示启动成功，进程仍可通过 `--status` 和 `--stop` 管理。Linux/macOS 需要 curl。脚本不会安装依赖、注册系统服务或配置开机自启。

正常启动或 `--restart` 时，如果 `JAVA_HOME` 无效、找不到 Java，或检测到的版本不是 17，脚本会询问 JDK 安装根目录。Linux/macOS 输入包含 `bin/java` 的目录，Windows 输入包含 `bin/java.exe` 的目录；macOS 也可输入 JDK 包内的 `Contents/Home`。脚本验证 Java 17 后继续；无效路径或版本可重新输入，空输入或取消则终止。路径只用于本次运行，不保存，也不修改系统环境变量。无可交互终端或执行 `--check` 时只报错、不询问。

脚本开始执行时会立即显示当前操作，并在检查运行条件、启动后台进程、发送停止请求和等待退出时显示阶段提示；重启会依次显示停止和重新启动的进度。应用和本机 HTTP 接口就绪后才会显示访问地址。

## 升级提醒

本版本调整了发布态数据库数据源和公共 API 数据源的运行方式。升级完成后，历史发布链接中使用数据库或公共 API 数据源的页面需要重新发布一次，重新发布会为发布态数据库查询和公共 API 配置生成新的运行时记录。未重新发布的历史发布链接可能无法继续加载这些数据源。

## 配置文件示例

下面内容与发布包中的 `config/application.yml` 配置模板保持一致。默认连接本机 MySQL；使用远程 MySQL 时，先修改 URL 的主机和端口。首次启动只需在提示时填写数据库名；用户名和密码若仍为占位值也会交互询问。路径默认无需调整，其他设置按需修改。

```yaml
server:
  port: 8080
  servlet:
    context-path: /

spring:
  datasource:
    type: com.alibaba.druid.pool.DruidDataSource
    driver-class-name: com.mysql.cj.jdbc.Driver
    druid:
      url: jdbc:mysql://127.0.0.1:3306/?serverTimezone=GMT%2B8&useUnicode=true&characterEncoding=utf-8
      username:
      password:
      initial-size: 5
      min-idle: 5
      max-active: 20
      max-wait: 60000
  servlet:
    multipart:
      max-file-size: 50MB
      max-request-size: 100MB

mybatis-plus:
  type-aliases-package: com.zsq.datavisoolservice.model
  global-config:
    db-config:
      logic-delete-field: deleted
      logic-delete-value: 1
      logic-not-delete-value: 0
  configuration:
    map-underscore-to-camel-case: true

logging:
  config: classpath:log4j2-spring.xml
  level:
    cn.jay.repository: info

datavisool:
  # 以下路径都可选；常规部署未配置时以 Java 进程工作目录（user.dir）为默认基准。
  # license: /usr/app/datavisool-server/license
  # AI 两种 workspace 的子目录不同，具体默认规则见下方说明。
  # ai:
  #   storage-path: /usr/app/resource/ai-driven
  # resource-path.root 未配置时默认为 user.dir；子项默认映射到 root 下对应目录。
  # resource-path:
  #   root: /usr/app/resource
  #   image: /static/images
  #   cover: /static/covers
  #   avatar: /static/avatar
  #   remote-component: /static/components
  #   font: /static/font
  #   dynamic-script: /static/lib
  #   logo: /static/logo
  #   template-cover: /static/templateCover
  #   video: /static/videos
  #   model: /static/models
  file:
    image-max-size: 50MB
    avatar-max-size: 1MB
    max-size: 20MB
    video-max-size: 500MB
    model-max-size: 500MB
  migration:
    enable: true
  db:
    test-database-max-timeout: 10
  mode: PROD
  security:
    cors:
      allowed-origin-patterns:
        - http://127.0.0.1:5173
        - http://localhost:5173
```

如果你的部署是同源访问，通常可以不配置 `datavisool.security.cors`。如果当前服务不涉及文件上传，也可以把 `spring.servlet.multipart` 这段删掉。上面的 `datavisool.license`、`datavisool.ai.storage-path` 和整个 `datavisool.resource-path` 配置段都是可选的。常规部署以 Java 进程工作目录 `user.dir` 作为默认基准；`license` 和 `resource-path.root` 未配置时都使用该目录。

两种 AI workspace 的默认子目录不同：未配置 `ai.storage-path` 和 `resource-path.root` 时，AI Driven 任务工作区位于 `<user.dir>/ai-driven/workspaces`（附件暂存目录是 `<user.dir>/ai-driven/attachment-staging`），Agent 项目工作区位于 `<user.dir>/agent-project-workspaces`。如果只配置 `resource-path.root`，前者改为 `<resource-path.root>/ai-driven/workspaces`，后者改为 `<resource-path.root>/agent-project-workspaces`。只有需要自定义或迁移持久化目录时，才取消对应注释并填写路径。

## 属性说明

| 属性 | 作用 |
| --- | --- |
| `server.port` | 服务对外监听端口，浏览器和代理访问这个端口。 |
| `server.servlet.context-path` | 服务的上下文路径，通常保持为 `/`。 |
| `spring.datasource.type` | 指定使用的数据库连接池类型，这里是 Druid。 |
| `spring.datasource.driver-class-name` | MySQL JDBC 驱动类。 |
| `spring.datasource.druid.url` | 数据库连接地址，包含主机、端口、库名和字符集参数。 |
| `spring.datasource.druid.username` | 数据库用户名。 |
| `spring.datasource.druid.password` | 数据库密码。 |
| `spring.datasource.druid.initial-size` | 连接池启动时初始化的连接数。 |
| `spring.datasource.druid.min-idle` | 连接池最小空闲连接数。 |
| `spring.datasource.druid.max-active` | 连接池允许的最大活动连接数。 |
| `spring.datasource.druid.max-wait` | 连接池获取连接的最大等待时间，单位毫秒。 |
| `spring.servlet.multipart.max-file-size` | 单个上传文件的大小上限。 |
| `spring.servlet.multipart.max-request-size` | 单次请求的总大小上限。 |
| `mybatis-plus.type-aliases-package` | MyBatis Plus 的实体别名扫描包。 |
| `mybatis-plus.global-config.db-config.logic-delete-field` | 逻辑删除字段名。 |
| `mybatis-plus.global-config.db-config.logic-delete-value` | 已删除时使用的值。 |
| `mybatis-plus.global-config.db-config.logic-not-delete-value` | 未删除时使用的值。 |
| `mybatis-plus.configuration.map-underscore-to-camel-case` | 是否把下划线列名自动映射成驼峰字段。 |
| `logging.config` | 日志配置文件路径。 |
| `logging.level.cn.jay.repository` | 指定仓储层日志级别。 |
| `datavisool.license` | 授权文件目录；不配置时默认使用当前工作目录。 |
| `datavisool.ai.storage-path` | 两类 AI workspace 共用的存储基路径；未配置时各自回退到 `resource-path.root` 或 `user.dir`，并使用不同子目录。 |
| `datavisool.resource-path.root` | 运行时资源根目录，图片、封面等文件会放在这里；未配置时默认为 Java 进程工作目录 `user.dir`。 |
| `datavisool.resource-path.image` | 图片资源映射路径。 |
| `datavisool.resource-path.cover` | 封面资源映射路径。 |
| `datavisool.resource-path.avatar` | 头像资源映射路径。 |
| `datavisool.resource-path.remote-component` | 服务端组件资源映射路径。 |
| `datavisool.resource-path.font` | 字体资源映射路径。 |
| `datavisool.resource-path.dynamic-script` | 动态脚本资源映射路径。 |
| `datavisool.resource-path.logo` | Logo 资源映射路径。 |
| `datavisool.resource-path.template-cover` | 模板封面资源映射路径。 |
| `datavisool.resource-path.video` | 视频资源映射路径。 |
| `datavisool.resource-path.model` | 模型资源映射路径。 |
| `datavisool.file.image-max-size` | 图片上传大小上限。 |
| `datavisool.file.avatar-max-size` | 头像上传大小上限。 |
| `datavisool.file.max-size` | 通用文件上传大小上限。 |
| `datavisool.file.video-max-size` | 视频上传大小上限。 |
| `datavisool.file.model-max-size` | 模型文件上传大小上限。 |
| `datavisool.migration.enable` | 是否在启动时自动执行数据库迁移脚本。 |
| `datavisool.db.test-database-max-timeout` | 测试数据库连接时的最大等待时间，单位秒。 |
| `datavisool.security.cors.allowed-origin-patterns` | 允许跨域访问的前端来源地址列表。 |

## 手动前台启动（排障用途）

需要在前台观察 Java 原始输出时，可在 `server.jar` 所在目录手动执行：

```bash
java -jar server.jar --spring.config.location=/usr/app/datavisool-server/config/application.yml
```

该命令直接在当前终端运行 Java，不使用一键脚本的后台进程记录、状态和停止管理。正常部署请使用上方的平台脚本；修改配置后可通过 `--restart` 按停止后启动的流程重启。

如果你的服务需要固定端口，可以在 `application.yml` 中补充：

```yaml
server:
  port: 8080
```

## 部署后检查

部署完成后，请至少检查以下内容：

- 服务进程是否正常启动
- 数据库是否连接成功
- 前端页面是否可以打开
- 资源图片和文件是否可以正常加载

## 常见问题

- 如果启动失败，先查看服务日志。
- 如果数据库连接失败，检查 `application.yml` 中的数据库地址、账号和密码。
- 如果资源无法加载，检查 `datavisool.resource-path.root` 指向的目录是否存在且可写。
- 如果端口被占用，修改 `server.port` 后重新启动服务。

### 用户名唯一性升级检查

升级前请备份数据库，并检查未删除的用户是否存在重复用户名：

```sql
SELECT username, COUNT(*) AS account_count
FROM user WHERE deleted = 0
GROUP BY username HAVING COUNT(*) > 1;
```

如有结果，请先由管理员确认账号归属并处理重复用户名，再启动新版本。升级脚本会为未删除用户的用户名建立唯一索引；若仍存在重复，迁移会失败并停止启动，不会自动合并或删除账号。新建用户需指定至少 8 个字符、最多 72 个 UTF-8 字节的初始密码；已有账号密码不会因升级改变。
