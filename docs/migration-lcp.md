# 从 LCP 迁移到 DataVisool Web

简体中文 | [English](migration-lcp-en.md)

本文针对本仓库当前的 DataVisool Web 实现（应用版本 `2026.9.0`）。迁移的输入是 **LCP 导出的项目 ZIP**，不是旧软件安装目录或数据库。Web 版与桌面版的导入规则不同，请以本文为准。

## 当前状态

Web 版保留了旧项目包导入和部分旧组件转换能力。导入时会将可识别的旧数据转换为当前项目数据；导入成功只表示项目数据已写入，**不保证所有画面、数据和交互与 LCP 一致**。

目前没有按 LCP 应用版本号划定的完整兼容列表，不能仅凭“LCP 几版本”判断能否导入。下表依据当前代码和测试说明可识别的**包结构**，并非对全部真实项目的兼容承诺。无清单包、清单版本 1 缺少真实样本验证；真实项目资源和浏览器交互的全面验证仍未完成。

## 先判断手里的包

用压缩软件**只读查看** ZIP 根目录，先看是否有 `manifest.json`（项目包清单）。不要修改清单、解压后重新打包或手工绕过校验。

| 包的情况 | 当前 Web 版如何处理 | 边界和建议 |
| --- | --- | --- |
| 有清单，`format` 为 `light-chaser-project`，明文 `formatVersion` 为 2 或 3 | 可尝试导入，仍需通过项目数据、资源、引用及文件校验。 | 有非空 `projects` 列表时按多项目结构导入；否则按单项目导入。不是所有同版本包都保证可用。 |
| 旧清单的 `format` 为 `light-chaser-project`，版本为 1 或未写 `formatVersion` | 导入器会尝试兼容，按照是否有非空 `projects` 列表选择多项目或单项目流程。 | 缺少真实样本验证；即使格式被接受，也必须通过其余校验并逐项检查结果。 |
| 没有根目录清单，但 ZIP 内有**一个** `.lc` 项目数据文件 | 会进入旧包导入流程，读取该文件以及能识别的图片、字体、服务器组件和动态脚本。 | `.lc` 内容仍须是有效的旧项目依赖数据；没有真实样本验证。该流程不等同于带清单包的全部资源能力，视频、模型和外部资源需特别检查、必要时手动补充。 |
| 整包加密，清单中的 `encrypted` 为真、`encryption.mode` 为 `package`、`encryption.algorithm` 为 `passphrase-v1` | 输入正确导出口令后尝试解密，再按内部清单校验并导入。外层加密清单可以是版本 4。 | 外层版本不代表解密后的内部项目版本；内部必须是可识别的带清单项目包。错误口令、损坏的加密数据或不支持的算法不能导入。 |
| 带清单包的公共 API 或数据库配置采用受支持的 `enc:v1:` 字段加密 | 输入对应口令后尝试解密并导入配置。 | 需要正确口令；只迁移包内连接配置，不迁移数据库业务数据。 |

旧数据中的 `LCPZ1:gzip:` 和受支持的二进制式 `LCPZ` 压缩前缀也有兼容处理；不认识或损坏的压缩数据会报错。**清单中的格式版本是项目包格式版本，不是 LCP 软件版本。** DataVisool 自己的新项目包使用 `datavisool-project` 标识，也由同一入口处理。

## 哪些内容不能直接导入

| 情况 | 当前限制 | 处理方式 |
| --- | --- | --- |
| 只有旧软件目录、旧数据库、截图，或者单独的 `.lc` 文件 | 项目导入入口接收项目 ZIP，不直接升级旧软件目录或数据库；单独的 `.lc` 文件不是上述无清单 ZIP。 | 尽量回到 LCP 导出完整项目 ZIP；无法导出时，需要手动重建。 |
| 无清单 ZIP 中没有 `.lc`，或有多个 `.lc` | 无法确定旧项目数据，导入失败。 | 使用原项目重新导出一个完整的单项目包，不要直接改包内容绕过检查。 |
| 清单格式标记未知，明文内部版本小于 1 或大于 3 | 不受当前导入器支持；加密外层与解密后的内部清单分别检查。 | 确认使用项目导出包和正确的 DataVisool Web 版本；必要时从原 LCP 重新导出。重新导出不保证一定兼容。 |
| 加密模式、算法或旧压缩格式不受支持，或口令丢失 | 不能通过当前导入器自动解密或解压。 | 找回原口令，或在原 LCP 中重新导出受支持的包；无法访问原项目或口令时，不能保证恢复。 |
| ZIP 损坏、路径重复、必需文件缺失或清单校验失败 | 导入器会拒绝不符合校验要求的内容。 | 保留原包，检查源项目资源并重新导出；不要修改文件或校验值来强行导入。 |
| 包外的文件、服务和数据库业务数据 | 不会因为导入项目 ZIP 而自动复制。 | 在目标环境单独迁移、配置并验证这些资源和服务。 |

## 导入步骤

1. 在 LCP 导出项目 ZIP，保留原项目和原始包。查看导出警告，先补齐缺失资源。
2. 在 DataVisool Web 创建并打开**空项目**。导入会把入口项目的数据写入当前项目；不要用未备份的现有项目试导入。带多项目列表的包还会创建其他项目并尝试恢复其引用。
3. 在设计器中选择 **更多项目操作 → 导入项目**，选择 ZIP；加密包或加密数据源填写相应口令。
4. 留意导入结果及提示，检查资源和引用。导入可能创建资源和数据源记录，匹配的已有公共数据源也可能被复用；建议先在隔离环境验证。
5. 按下表逐项核对，确认无误后从 DataVisool 导出新项目包，并保留原始备份。

## 常见边界与处理

| 导入后或导入时的情况 | 原因与处理 |
| --- | --- |
| 旧自定义组件无法转换、整个包导入失败 | 仅识别可静态确定的旧接口及部分旧样式；未知成员、动态访问、入口不明确或无法安全转换的代码可能被拒绝。按错误提示定位组件。保留备份后，可在 LCP 中移除该组件并重新导出；导入后按[组件开发说明](zh-cn/develop/index.md)重新构建和上传，再手动恢复配置及蓝图。转换成功也需要验证运行效果。 |
| 图片、字体、视频或 3D 模型缺失 | 检查原包及其导出警告。包外文件不会自动补齐；能识别的包内资源才会尝试映射。无清单旧包仅扫描图片、字体、组件和脚本目录；视频、模型等需检查并可能手动补充。目标环境还需要能访问外部 URL，视频编码也需浏览器支持。 |
| 同名资源无法确定、字体冲突或文件校验失败 | 检查原项目是否引用了多个同名但不同内容的文件，调整资源名称或引用后重新导出；不要手工修改校验信息。 |
| 公共 API 或数据库需要重新选择 | 无法映射的引用会被清空并给出提示。在目标站点配置并重新选择数据源，核对地址、凭据、权限及网络，再测试。导入连接配置不等于迁移业务数据。 |
| 多项目、子项目或大屏引用不完整 | 带 `projects` 列表的包依赖完整的项目节点及引用；缺少被引用项目或存在循环引用可能导致失败。回到 LCP 检查引用并重新导出。单项目包中无法映射的大屏引用会被清空并提示，需要手动重选。 |
| 加密包提示缺少口令或解密失败 | 输入原导出口令；检查包是否完整，以及模式和算法是否属于上表支持范围。字段加密和整包加密都可能需要口令。 |
| 地图、动态脚本、蓝图或组件显示与旧版不同 | 对照旧项目逐项验证，重新配置不兼容的地图、脚本或交互；导入不保证旧运行时行为完全一致。 |
| 文件过大 | 当前导入器对项目文本、单个文件及累计解压数据设有限制；上传服务也可能有额外限制。检查服务端错误，缩减资源并从 LCP 重新导出。 |

更多导入操作见[导入与导出项目](zh-cn/functions/main_desiner/export_import.md)；源码级兼容规则与验证范围见[旧项目包导入兼容清单](../datavisool-doc/旧项目包导入兼容清单.md)。
