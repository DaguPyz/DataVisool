# Web 用户手册迁移记录

用户手册从 `light-chaser-pro-doc` 的 `docs/` 迁入主仓。旧目录基准为 2026-10-18 的提交 `d7cfae505f95455528e89d436cfe0c42ed87c9bb`，其中有 79 个 Markdown 文件。当前部署的入口是 `/docs`，登录用户也可以选择“帮助 → 使用文档”。

## 旧目录的去向

[文章目录](../docs/zh-cn/navigation.json)逐项记录了旧目录的处理结果。同一条记录决定侧栏位置、文章路径和旧书签目的地。目录层级用 `depth` 表示，顶层为 0。

| 处理方式 | 范围 | 阅读位置 |
| --- | --- | --- |
| 迁入并校对 | `articles` 的 63 篇，含原侧栏外的使用教程和项目级动态脚本 | `/docs/zh-cn` 及其子页 |
| 保留旧版入口 | `archive` 的 11 篇，含桌面安装、独立运行时、废弃的 Docker 方式及两篇旧部署入口 | `/docs/archive` 下的对应文章，归档首页另行编写 |
| 合并旧入口 | `develop.md` 对应组件开发总览，`functions/blue_print/logic_node.md` 对应功能节点，`log/log.md` 对应官网更新日志 | `legacyAliases` 记录目的地址；原侧栏的外部更新日志链接在 `external` |
| 站点配置 | `sidebar.md`、`_coverpage.md` | 旧地址对应新版首页。导航和首页正文分别由 JSON 与 Markdown 维护 |

首轮试点拍摄的截图和沿用的旧手册配图在正文中区分。构建只读取导航登记的文章和其中展示的图片，保留源文相对目录，排除旧站样式、脚本、未引用的图和作图原稿。

## 后续更新

1. 在 `docs/zh-cn/` 修改正文。新增页面时在 `navigation.json` 登记位置。文中用 Markdown 相对路径或以手册根目录为起点的路径引用文章，例如 `/deploy/web.md`。图片随文章保存。
2. 标题改名时，将仍需兼容的旧标题片段登记在 [历史章节映射](../docs/zh-cn/legacy-headings.json)。构建在发现正文链接、图片或站内章节缺失时会报出来源页。
3. 在仓库根目录执行 `pnpm -F datavisool-app build`。文章、搜索索引和配图随 Vite 产物进入 Spring Boot 发布包。打开任一内页直接刷新即可核验部署的前端路由。

## 官网切换与回退

旧文档仓 `light-chaser-pro-doc/docs/index.html` 会先检查目标站的 `/assets/docs-site-ready.svg`。新手册就绪时，浏览器把完整旧书签交给新站解析。未检测到标记时，原 Docsify 继续提供服务。

- 同域部署时，旧的 `/docs/` 静态入口和快照资源可保留，`/docs/zh-cn`、`/docs/archive` 及其子路径和新版的 `/assets/` 要路由到 Web 服务。
- 跨域部署时，在旧入口的 `datavisool-docs-public-base` meta 中填写读者可访问的新站源（协议、域名及可选端口）。正式公网地址由部署方确定。桌面端如需加链接，应选其版本适用的公开文章。
- 在旧站地址查询参数加 `snapshot=1` 可强制打开原站快照并保留 `#/` 书签。若 Web 帮助入口也要回退，构建前设置 `VITE_USER_GUIDE_URL=https://lcpdesigner.cn/docs/?snapshot=1#/`。恢复新版入口时，清除此覆盖并重新构建。
